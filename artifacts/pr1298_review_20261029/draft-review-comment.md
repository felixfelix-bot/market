Thanks @plebomoto — the fail-closed posture, the marker-before-index ordering and the `DocCount` validation are the right shape. Reviewed at merged tip `d205c158`; posting as a comment because the PR is already merged and all four items are still on `master`.

1. [RISK] `deploy-simple/relay/cmd/market-relay/main.go:205` — `Close()` takes the write lock, but every `QueryEvents` yield at `main.go:218-224` runs under `RLock`, and the pinned khatru yield is `ws.WriteJSON` with no write deadline (`khatru/responding.go:33`; `handlers.go:131-133` sets read deadlines only). A stalled subscriber wedges `cleanup()` past `server.Shutdown`'s 10 s context until SIGKILL at `TimeoutStopSec=120`. Reproduced at head: `Close` blocked until the stalled reader was released, and new queries queued behind it. Before this PR `Close` was a no-op, so the process exited promptly — the wedge is new. A bounded drain (lock-acquire timeout, or a per-write deadline) would close this.

2. [RISK] `deploy-simple/relay/cmd/market-relay/main.go:289` — the eviction loop deletes every previously stored document from search with no `nostr.IsOlder` comparison, then skips the search save because raw refused the older event (`eventstore/boltdb/replace.go:38-48`, `shouldStore=false`). Republishing an older profile/contact/list event therefore evicts the newest live event from search permanently while raw keeps it. Reproduced at head: `raw_has_newer=1`, `search_finds_newer=0`. The loop is byte-identical at base `4cbe2b26`, so it is pre-existing — but it is exactly the raw/search divergence the "preserve stores" invariant should cover, and it is one comparator away from fixed.

3. [RISK] `deploy-simple/relay/internal/searchindex/index.go:69` — `Prepare` accepts any existing index directory without checking it against the raw store. An out-of-band relay start between `--rebuild-search-to` and the runbook's `mv -T` activation leaves post-rebuild events durably in raw and permanently absent from search, with no error and no log line. Reproduced at head (rebuild → start → publish → activate → start: `late event present in search: false`). The existing nit on this line is readability; the gap is missing parity. Comparing the prepared index's doc count (or a build stamp) against the raw store before `Init()` would catch it.

4. [NIT] `deploy-simple/relay/internal/searchindex/index.go:54` — `create()` Mkdirs the index directory and then calls `bleve.New` with no marker and no cleanup on failure. A crash in that window leaves a marker-less, metadata-less directory that fails closed on every subsequent start (`metadata missing`), so a first boot can wedge until an operator removes the directory. Reproduced. `Rebuild` already writes `.rebuild-incomplete` before `bleve.New`; the same ordering here would make the wedge self-healing.
