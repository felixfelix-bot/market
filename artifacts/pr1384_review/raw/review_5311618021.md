## Findings

[RISK] `reconcileMultipartyLeg` can never resolve a row settled `uncertain` — src/lib/auction/multipartyLegJournal.ts:355 (`if (row.state !== 'attempted') continue`). The row-state contract at :54-56 says "`planned` and `attempted` are the only ones with an outgoing transition … only reconciliation may resolve `uncertain` further", and D17's text says an uncertain row "stays `uncertain` until evidence … resolves it". But reconciliation skips every non-`attempted` row, so once a caller settles a row `uncertain` (settleMultipartyLegRow accepts that outcome via MultipartyLegRowOutcome, :63), later valid evidence can never upgrade it — repro: settle row 0 `uncertain`, then reconcile with that row's verified proofs → `resolved=[]`, row stays `uncertain`, leg verdict stays `uncertain` forever. Not reachable from production yet (no callers), but Gate E's live half is specified to consume exactly this path.

[RISK] Evidence contradicting a settled row is silently dropped — src/lib/auction/multipartyLegJournal.ts:355-363. Valid proofs arriving for a row already settled `failed_pre_mint` are ignored (`resolved=[]`), and symmetrically a `provenPreMintFailure` for a row settled `locked` would be. The within-pass contradiction check (`journal_evidence_contradictory`, :319-324) only sees one pass's evidence, not evidence-vs-settled-state. D17: "Resolution is evidence, and only evidence" — dropping verified evidence inverts that: a row that IS locked stays recorded as provably-not-locked, and `summarizeMultipartyLeg`'s `lockedRowIndexes` (the reclaimable set) under-reports it. Either resolve-on-evidence or refuse loudly; silence is the one option D17 forbids.

[NIT] The `unsent` sentence is false for an all-`failed_pre_mint` leg — src/lib/auction/multipartyLegJournal.ts:256 "No swap was sent yet…" vs test multipartyLegJournal.test.ts:294-298 which deliberately lands that state in `unsent`. Swaps were sent; they provably failed pre-mint. One sentence per state (D14) should not assert "nothing has to be recovered" about a leg whose inputs were consumed by requests that failed before the mint — those inputs' fate is exactly what the caller must re-check.

[NIT] `planMultipartyLegSwaps` validates the refund key's shape but passes each row's `childPubkeyCompressed` through unvalidated (src/lib/auction/multipartyLegSwapPlan.ts:198-201) — the lock planner does refuse non-compressed row keys upstream (multipartyLegLockPlan.ts:143), so this is defense-in-depth asymmetry only, but the module already chose to validate hand-built inputs (its own `swaps_mint_mismatch` refusal exists for exactly that case).
